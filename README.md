# AsteroidProxOps
The material is based on work supported by the NASA Space Technology Graduate Research Opportunities Award No. 80NSSC23K1199 titled:
Autonomous Landing and Proximity Operation Technology for Poorly-Characterized Small Bodies

The scripts in this repository will regenerate the data presented in the journal paper titled:
Remote Guidance of a Mothership-Daughtership Formation for Asteroid Exploration by Logan Feld, Dr. Shyam Bhaskaran, Dr. Andrew French, Dr. Joshua Lyzhoft, and Dr. Koki Ho

The goal of this work is to enable spacecraft to autonomously navigate the uncertain shape and gravity models around asteroids and other small bodies.

The main contributions to the project thus far are formulating two versions of a model predictive control (MPC) formulation to autonomously perform proximity operations around the asteroid Apophis amidst gravitational and thruster uncertainties. The three spacecraft, denoted the mothership, daughtership 1, and daughtership 2, are to perform tomographic characterization with a bistatic radar. The mothership estimates her own state with an extended Kalman filter (EKF) using simulated images of Apophis' surface with a nadir-pointing camera. The daughtership states are updated by accumulating image and range measurements from the same mothership camera within a batch least squares (BLS) filter. Additionally, the BLS also estimates any ΔV performed by the daughterships to account for thruster uncertainties. The polyhedral shape models of the asteroids within this repository are from the NASA Planetary Data System [1]. 

## How to run:
```sh
conda create -n ENV_NAME python=3.9.13
conda activate ENV_NAME
pip install poetry OR conda install poetry
poetry install
```
Confirm environment by running the test scripts.
In the root directory, run:
```sh
pytest
```
## The output folder:
The output folder contains all the figures generated by the repository within Python. The figures seen in the journal paper are instead plotted with MATLAB. output/MATLAB_mats contains all the necessary data for generating these plots within MATLAB. Copying this folder or adding it to your MATLAB path and then running ApophisProxOpsV1_0Plots.m or ApophisProxOpsV2_0Plots.m for whichever version's data you have will generate the plots as seen in the journal paper. Note that V1.0 data is not compatible with the V2.0 plot code and vice versa.  

## The config files:
All the config files that the source code reads from are set up to regenerate all the results of the journal paper as is. The config files are found in the 'input' folder in the repository. Any of the config files can be edited except for the 'config_for_testing.ini' config file. This config file is specifically used for the pytest test scripts to ensure the repository is cloned properly, so it is recommended that this testing config file remains unchanged. config.ini is the config file used to run a single MPC simulation (regenerating the V1.0 or V2.0 results depending on which branch you are in) and can be edited freely.

The following section will go through what each line in a config file means explicitly. The values used for these parameters in the various simulations can be found in Table 1 of the journal paper.

## Config file section - Simulation:

Tmin: min thrust of the spacecraft in Newtons (must be non-negative)

Tmax: max thrust of the spacecraft in Newtons (must be non-negative and higher than Tmin)

m_wet: wet mass of the spacecraft in kilograms (must be positive)

m_dry: dry mass of the spacecraft in kilograms (must be lower than m_wet and positive)

S: surface area of the spacecraft cannonball model for SRP (in square meters)

numstates: the number of states in the state vector (the paper uses 7 (3 position, 3 velocity, 1 mass) and it is not recommended changing this unless you update parts of the code accordingly)

m: number of controls in the control vector (the paper uses 4 (3 acceleration, 1 slack varable) and it is not recommended changing this unless you update parts of the code accordingly)

isp: specific impulse of thrusters in seconds (must be positive)

designations: strings for what each spacecraft should be called (it is not recommended changing this unless you update parts of the code accordingly)

folder: folder name within the trajdata folder that contains ephemeris data and reference trajectories (if used)

dxhat_0: estimated initial x position deviation from truth in kilometers in the asteroid body fixed frame

dyhat_0: estimated initial y position deviation from truth in kilometers in the asteroid body fixed frame

dzhat_0: estimated initial z position deviation from truth in kilometers in the asteroid body fixed frame

dvxhat_0: estimated initial x velocity deviation from truth in kilometers/sec in the asteroid body fixed frame

dvyhat_0: estimated initial y velocity deviation from truth in kilometers/sec in the asteroid body fixed frame

dvzhat_0: estimated initial z velocity deviation from truth in kilometers/sec in the asteroid body fixed frame

horizon: number of timesteps in the MPC prediction horizon (must specify for each spacecraft, must be an integer >= 1)

Px: state covariance matrix diagonal value for x position in square kilometers (must be non-negative)

Py: state covariance matrix diagonal value for y position in square kilometers (must be non-negative)

Pz: state covariance matrix diagonal value for z position in square kilometers (must be non-negative)

Pvx: state covariance matrix diagonal value for x velocity in kilometers squared / sec squared (must be non-negative)

Pvy: state covariance matrix diagonal value for y velocity in kilometers squared / sec squared (must be non-negative)

Pvz: state covariance matrix diagonal value for z velocity in kilometers squared / sec squared (must be non-negative)

Pq: state covariance matrix diagonal value for mass in square kilograms (must be non-negative)

a_r: largest unmodeled acceleration for the spacecraft in the radial direction in the RTN frame in kilometers / sec squared

a_t: largest unmodeled acceleration for the spacecraft in the transverse direction in the RTN frame in kilometers / sec squared

a_n: largest unmodeled acceleration for the spacecraft in the normal direction in the RTN frame in kilometers / sec squared

v: all measurement noise covariance values in various units (must be non-negative. Current setup: indices 0, 1 are mothership camera pixel coord covariances in pixels squared, 2, 3, 4 are daughtership 1 camera pixel coord covariances in pixels squared and range measurement noise covariance in kilometers squared, 5, 6, 7 are daughtership 2 camera pixel coord covariances in pixels squared and range measurement noise covariance in kilometers squared

v_start: indices in which the v vector splitting per spacecraft start

v_end: indices in which the v vector splitting per spacecraft end

fov: camera field of view (FoV) angle in degrees. Camera always assumed pointing at the CoM of the asteroid (nadir pointing). Note this is not the half angle, but the full FoV (must be positive)

f: camera focal length in millimeters

pixel_pitch: camera pixel pitch in pixels / millimeter

width: camera image width in pixels

height: camera image height in pixels

ref_traj_setting: whether or not to generate a reference trajectory in the code (0) or to use existing reference trajectories from folder (1)

ics_gen_setting: if ref_traj_setting = 1, this setting will determine if the code should generate initial conditions itself using r_0, ta_0, t_0 (0) or if it should use existing initial conditions provided in x_0, y_0, z_0, vx_0, vy_0, vz_0 (1)

x_0: initial true x positions in the Apophis-centered inertial frame in kilometers. Only used if ics_gen_setting=1

y_0: initial true y positions in the Apophis-centered inertial frame in kilometers. Only used if ics_gen_setting=1

z_0: initial true z positions in the Apophis-centered inertial frame in kilometers. Only used if ics_gen_setting=1

vx_0: initial true vx velocities in the Apophis-centered inertial frame in kilometers / sec. Only used if ics_gen_setting=1

vy_0: initial true vy velocities in the Apophis-centered inertial frame in kilometers / sec. Only used if ics_gen_setting=1

vz_0: initial true vz velocities in the Apophis-centered inertial frame in kilometers / sec. Only used if ics_gen_setting=1

r_0: desired initial orbital radius for each reference trajectory in kilometers. Only used if ics_gen_setting=0

ta_0: desired initial orbital true anomalies for each reference trajectory in radians with 0 being the Apophis Z-axis. Only used if ics_gen_setting=0

t_0: desired initial time epoch for each reference trajectory in number of epochs in the provided ephemeris. Only used if ics_gen_setting=0

N: number of time steps to be simulated

N_ref: number of time steps of the ephemeris data to store into arrays for access. Should be at least dt_MPC_multiplier * horizon number of steps more than N.

dt: time step duration in seconds

dt_MPC_multiplier: number of time steps simulated between MPC prediction horizon steps/epochs

k: order of the ephemeris BSpline interpolation. Must be an odd integer > 1.

N_batch: number of measurement epochs before the BLS runs to update the daughtership states

gates_1_factor: the number of the Gates model fixed-magnitude error standard deviations that will be the ΔV threshold

C_R: reflectivity coefficient. Must be a value between 1 and 2 (inclusive)

model: string for what BLS measurement model to use. Currently only supports image_range, but other models can be implemented through modification of the BLS.py script

orbit: string for whether generated reference trajectories should be terminator or halo orbits. halo highly recommended as terminator orbits are unstable

## Config file section - Asteroid:

asteroid: string for what asteroid the code is to be run with respect to. Can be one of the following values: bennu, kleopatra, geographos, bacchus, toutatis, castalia, golevka, itokawa

fnum: number of features to be randomly placed around the Landing Site (must be a positive integer)

## Config file section - Gates:

s1: Gates model sigma 1 - fixed magnitude error standard deviation in millimeters / sec

s2: Gates model sigma 2 - proportional magnitude error standard deviation as a percentage

s3: Gates model sigma 3 - fixed pointing error standard deviation in millimeters / sec

s4: Gates model sigma 4 - proportional pointing error standard deviation in milliradians

## How to run a single MPC simulation:

Within the repository, select the branch for the version you desire to run simulations for, update input/config.ini to have the desired initial and final conditions or keep it the same to regenerate the same MPC results as seen in the journal paper. Run src/MPC.py. This will generate the necessary MATLAB .mat files for you in output/MATLAB_mats. Then add those to your MATLAB path and run the corresponding MATLAB plotting script
